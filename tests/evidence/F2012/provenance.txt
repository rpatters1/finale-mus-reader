Finale 2012 (internal version 17.0), zlib era, little-endian.

Origin: a test case authored for the Note Spacing plug-in and released for
publication by its author.

The fixtures authored here were saved under Mac OS X 10.7.5 running in UTM, which
is the host for every Finale after 2006. The exact application build is not
recorded.

This file is a back-save. Finale 2014 through Finale 27 can write a musx document
out as a Finale 2012 MUS file, and that is what happened here, which is why the
name in the original collection refers to Finale 2014 while the banner reads
"Finale(R) 2012 File Converter". The two header tuples record the two roles: the
creator tuple keeps the authoring application, internal 18.0 for Finale 2014, and
the last-saver tuple records the format actually written, internal 17.0 for
Finale 2012. Reading the last-saver tuple therefore yields the version that
governs the file's layout, which is what the reader gates on.

F2012-dblsharp-insert-outside-BMP.mus
    sha256 e44f2e985b0213baf494eb4bfb5c0456e6536432182257a21df5d3e011c755a0
    From F2012-baseline, the double-sharp insert's character set to U+26469 in LiSong Pro.
    The element stores 69 64 02 00 at byte 16 and 19 at byte 10; the companion reads
    <symChar>156777</symChar> with fontID 19. A character above the basic multilingual plane
    is the only value that can fix the byte order of that era's widened character: low word
    first gives 156777, while the high-word-first order the two trackings use in the same
    element would give 0x64690002, which is not a codepoint. One element therefore holds two
    different 32-bit conventions.

F2012-lyric-punct.mus
    sha256 fb44a24bd7f81b86c6b84f6c6fe25e7505e9c730d08f953b3871b1cb580bf912
    From F2012-baseline, the Lyric Options punctuation set changed to `#@%&` with "Ignore
    Syllable Edge Punctuation" left on. Four characters sharing nothing with the stock set
    `,.?!;:'"“”‘’`, so finding them proves where the field begins rather
    than matching a default.
    This is the only specimen anywhere that carries the list at all. Finale writes it as a
    variable-length tail on selector 57, class 0x0047, and **only when the list is not the
    stock one**: the record is twelve bytes in every one of the 1,189 companion-backed corpus
    documents and in the other five Finale 2012 fixtures, and twenty-four here -- the six
    scalars unchanged, then the four characters as 16-bit code units and a zero. An absent
    tail therefore means the stock list, which musxdom's integrityCheck already supplies.
    Two things changed that the edit did not ask for, both Finale normalizing as the dialog
    closed. The word extension connection table gained vertical offsets of 5 on five of its
    nine styles and 1 on a sixth, which makes this a welcome second specimen for a mapping
    that otherwise rests on one Finale 2006 fixture. The font definition table also renumbered
    Lucida Grande and Symbol from comparators 11 and 13 to 15 and 16.

    the two documents are the same two bookmarks on either side of the boundary.

    It settles two things about the modern form. **Bookmark text is an ordinary
    text-pool record** from this release, keyword `bookmark`, `^end`-terminated like
    every other record of the era and carrying no style commands of its own. And
    **the text is UTF-8**, shown rather than inferred: `c3 bc` is the u-umlaut of
    `Page über` and `c2 ab c2 bb` is the guillemet pair of `Scroll «» Bookmark`,
    where the same characters are one byte each in every earlier era.

    The comparators are not stable across the upgrade. The same two bookmarks are 1
    and 2 in the Finale 3.7.2 companion and 2 and 3 here.

    A caution about the specimen. The upgrade prepended mojibake to the bookmark
    text, which was removed by hand before this save; the file is therefore an
    edited artifact rather than a raw conversion. Whether the corruption came from
    the character encoding or from Enigma tags the upgrade did or did not expect is
    not established, and this document does not answer it.

F2012-ssline-offsets.mus
    sha256 55ea2ec26ef98f70986a8e0c50b8449fb5e2b199b387187ae24eb13a5106e2d8
    F2000-ssline-offsets back-saved to Finale 2012, so that one document states the same six
    custom line styles in both the fixed-row layout and the Unicode-era class layout. Finale
    adds a seventh of its own, the synthesized default it puts in every upgraded document.
    It is the fixture that corrected how the Finale 2012 character widening shifts the record.
    The widened character belongs to the Char parameter block, so only that block's own later
    fields move with it: cmper 5's font id, size, mask and baseline shift each sit one word
    later than in the fixed-row source, while cmper 4's dash lengths sit exactly where the
    earlier layouts put them. Everything after the parameter block moves for all three line
    styles, which cmpers 3 and 6 show. Read through a rule that shifted every slot alike, this
    document reports a dashed line whose gap is zero.
    Its Char line also shows that the era stores a code point rather than a byte: the character
    the fixed-row source holds as Mac Roman 199 is 171 here, which is what the fixed-row
    reader arrives at by decoding.
