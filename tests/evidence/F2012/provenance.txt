Finale 2012 (internal version 17.0), zlib era, little-endian.

Origin: a test case authored for the Note Spacing plug-in and released for
publication by its author.

The fixtures authored here were saved under Mac OS X 10.7.5 running in UTM, which
is the host for every Finale after 2006. The exact application build is not
recorded.

This file is a back-save. Finale 2014 through Finale 27 can write a musx document
out as a Finale 2012 MUS file, and that is what happened here, which is why the
name in the original collection refers to Finale 2014 while the banner reads
"Finale(R) 2012 File Converter". The two header tuples record the two roles: the
creator tuple keeps the authoring application, internal 18.0 for Finale 2014, and
the last-saver tuple records the format actually written, internal 17.0 for
Finale 2012. Reading the last-saver tuple therefore yields the version that
governs the file's layout, which is what the reader gates on.

F2012-upstem-flags.mus
    sha256 f95d2ea21b99022e41025012a57de6afef2f97184e85df62e15cc61e58fb7df6
    The tracked fixture for the 2007-2012 record encoding, which shares the
    logical model of class, comparator, and incidence with every earlier era but
    none of the physical one: records are class-identified and length-governed
    rather than fixed 16-byte rows. It carries sixteen font definitions and is
    the regression test for that separate decoding pathway.

F2012-insert-flat-tracking.mus
    sha256 09f662ca4ef7c61c34e2810b6c8c4a63cc8f5b25f9dc77256ed024136df49aa5
    The same edit as F2005-insert-flat-tracking, in the 20-byte element layout: tracking
    before 1000, tracking after 250, baseline shift -25. A little-endian file stores 1000 as
    00 00 e8 03, which is the same two-words-high-word-first rule the big-endian era uses
    rather than a plain long.

F2012-dblsharp-insert-outside-BMP.mus
    sha256 e44f2e985b0213baf494eb4bfb5c0456e6536432182257a21df5d3e011c755a0
    From F2012-baseline, the double-sharp insert's character set to U+26469 in LiSong Pro.
    The element stores 69 64 02 00 at byte 16 and 19 at byte 10; the companion reads
    <symChar>156777</symChar> with fontID 19. A character above the basic multilingual plane
    is the only value that can fix the byte order of that era's widened character: low word
    first gives 156777, while the high-word-first order the two trackings use in the same
    element would give 0x64690002, which is not a codepoint. One element therefore holds two
    different 32-bit conventions.
