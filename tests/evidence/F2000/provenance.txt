Finale 2000 (internal version 5.0), uncompressed fixed-row era, big-endian.

Origin: a test case authored for the Mass Copy plug-in and released for
publication by its author.

F2000-empty.mus and the fixtures derived from it have a different origin: they were
authored in Finale 2000 itself, running under SheepShaver, by this repository's author.
F2000-empty.mus is a new document made with File > New, saved without any edit, and is
their common parent. It exists because the Mass Copy documents above cannot be moved into
that virtual machine, so a derived fixture cannot use one of them as its parent; a copy of
it is kept inside SheepShaver so that further fixtures can be derived from the same file.
It is structurally the same document as F2000-baseline.mus and differs from it only in the
bytes a fresh save rewrites.

F2000-lyropts-align-just.mus
    sha256 e10296cf6fed3509c277de624806499d440eece2021ce0fb3ce8a8620e64e1e3
    From F2000-multilayer, not F2000-baseline: the first syllable's alignment set to Right and
    the system-start syllable's justification set to Right. Finale 2000 is the first release
    with a dedicated Lyric Options dialog, whose addition to the four settings Finale 3.x
    already had is exactly this syllable positioning table.
    This is the only document in any survey that uses the legacy alignment value 3. Across all
    1,189 companion-backed documents of the reference corpus, not one carries `right` as either
    an alignment or a justification for any of the four positions, so before this fixture that
    member of the enum rested on the framework's LYRICS_ALIGN_ constants alone. It supplies the
    value twice over, once as an alignment and once as a justification, so a mapping that
    translated only one of the two fields would fail on it.
    Against its parent the only options record that moves is selector 87 incidence 1: word 6
    goes 1 to 3 and word 10 goes 2 to 3, and both positions' flag words gain 0x8000 because
    setting a position's alignment enables it. The companion reads first as right/left with
    <on/> and systemStart as center/right with <on/>, while the word extension position stays
    off -- so one record carries both states of the flag bit.
    Its ETF is not a corroborating export: it contains no (65534) rows at all, against 294 in
    F2000-baseline.etf, so it was written with options excluded.

F2000-ssline-offsets.mus
    sha256 b53b944dd389fd39ec8f5767a055a674478c4a8f08fdf545dee919f14535cdb0
    From F2000-empty, with four custom line styles added as cmpers 3 through 6. Together they
    exercise every layout the `ls` record has, and every value is chosen so that no two slots
    of the same record can be confused.
    Cmper 3 is a Solid line with all five text anchors defined and every position box carrying
    a distinct prime: the anchors take 11/13, 17/19, 23/-29, 31/37 and 41/43 as H and V, and
    the line adjustments take 47 for Start H, 53 for Cont H, 59 for End H and 61 for V. The one
    negative value exercises sign on a big-endian source. This is the record that established
    words 19 through 33, which before it were presumed from position alone: the X and Y offsets
    interleave per anchor rather than being grouped by axis, and the five line adjustments
    follow in the order musxdom declares them. It also settles what no earlier sample could
    distinguish, that the single "V" control writes one value into both word 30 and word 32, so
    a document never has `lineStartY` and `lineEndY` disagreeing.
    Cmper 4 is Dashed with a 3 EVPU dash and a 7 EVPU gap. Every earlier sample had the two
    equal, which left the order of words 2 and 3 assumed from musxdom's declaration order; 192
    against 448 tells them apart.
    Cmper 5 is a Char line set in Arial, bold and italic, at size 17 with a -83 EMs baseline
    shift. It established words 2 and 4 as the font id and the Enigma style mask, completing
    the ordinary legacy font tuple of id, size and mask across words 2 to 4. Its character is
    also the only evidence that a stored character is a byte in its *font's* encoding rather
    than a code point: the file holds Mac Roman 199 and the companion reads 171.
    Cmper 6 is Solid with a Hook start cap of 1984 EFIX and a custom arrowhead end cap naming
    shape 2, so each cap's shared value slot is exercised as both of the things it can be, and
    words 10 and 12 are shown to stay zero while 9 and 11 are in use.
    Against its parent the only records that move are `ls` cmpers 3 through 6, which the parent
    does not have at all, the five smart shape text blocks cmper 3's anchors reference, and the
    font definition Arial takes.

    From F2000-empty, with tie options edited as a discriminator for the hypothesis that Finale's
    pre-2002 conversion copied tie controls into modern Smart Shape slur-thickness controls. The
    fixed-global options diff changes only selector 84 incidence 0: thicknessRight moves from 6

    relevant option subtrees. SmartShapeOptions is identical to the parent's companion, including
    slurThicknessCp1Y and slurThicknessCp2Y at 6. The fixture therefore rejects direct copying of
    these tie thickness values into the Smart Shape controls.
